# Newgame 대응 씨앗 구현·검증 판정

TASK-20260915-NEWGAME-PARITY-001 / EXE-20260915-NEWGAME-PARITY-001

v0.11.0 후보는 문서만 있는 씨앗에 운영 원본 수집, 업무 상태 파생, 인증된 판단, 읽기 전용 오프라인 모드, OOP 탐색, 제한된 Canary 배포 어댑터와 감사 복원을 추가했다. `View to OOP, Set up to DOP`를 유지한다. **Newgame 전체 기능 동등성을 완료했다고 판정하지 않는다.**

| 영역 | 이번 구현·관측 | 남은 동등성 조건 |
|---|---|---|
| P01 수집 | 승인된 로컬 문서/코드/자료 hash·stable ID·누락/충돌 | 의미 관계 자동 추출, 외부 snapshot 어댑터 |
| P02 문서 계층 | 원본 디렉터리에서 다단계 문서 생성; 3단계 실브라우저 조회 | MkDocs 전체 문서/플러그인 표현 |
| P03 업무 상태 | Event 기반 업무·Core 검증·인간 수락·배포 4축 | 과거 프로젝트 업무 판단의 명시적 이관 |
| P04 탐색 | 개요/판단 대기/검색·필터·페이지/객체 상세/근거/문서 | 실제 대규모 문서의 인간 가독성 수락 |
| P05 최신성 | 원본/Task revision/입력 계약 변경 시 승인 효력 제거 | 외부 자료의 신선도 SLA |
| P06 권한 | principal+capability, 자기승인 금지, 원본/행동 서버 경계 | 독립 실제 계정 운영, OS/IAM 격리 |
| P07 검사 | 기존 Core 실제 Run과 연결 원본 바이트 일치 | 각 프로젝트 검사 충분성의 독립 검토 |
| P08 배포/회수 | 고정 어댑터·불변 후보·기존 active 확인·관찰·rollback·reconcile | 실제 cloud/CI, 장기/다중 cohort 확대, 운영 복구 |
| P09 보호된 조회 | 문서·검색·선행 관계 필터, 전역 이벤트 건수 대신 opaque 근거 참조 | 실제 원본의 민감도 분류와 접근 감사 |
| P10 품질 | 빈/중복/누락/틀린 상태 거부; 1280/390px 합성 화면 관찰 | 실제 프로젝트와 Newgame 내부 화면 수락 |
| P11 외부 통합 | 외부 수집/CI/도메인 도구의 필수 어댑터 계약 | Notion/Sheet/Cloudflare 등 실제 범용 connector |
| P12 최적화 | 동일 출력·실패 상태 유지 시 Core.status 24→1회 | 실제 규모/장기 비용·규칙·인간 개입 감소 |

최적화의 정확한 측정은 같은 실행의 optimization.json에 있다. 합성 게임/물류 명칭은 서로 다른 실제 도메인 운영의 증거가 아니다. 24개 업무 객체의 동일 Task 참조 workload에서 관측을 재사용한 개선이며, Newgame보다 전체적으로 빠르다는 주장이 아니다.

초기 17원칙의 계약 추적은 17/17, 로컬 부분 메커니즘 연결은 G15의 동일 출력 비교를 추가하여 **15/17(88.2%)**이다. 남은 계약·평가 항목은 G09(교차 프로젝트 일반화), G17(장기 신뢰/개입 감소)이다. 원문 전체 수락 기록은 여전히 0/17이다. 이전 14/17(82.4%) 감사는 역사로 유지한다. 이 숫자는 기능 완성률이 아니다.

Newgame의 장점은 실제 프로젝트 문서와 도메인 도구·CI·배포 운영이 연결돼 있다는 점이다. 이번 씨앗의 장점은 명시적 데이터 계보, 바뀐 수락 계약의 승인 무효화, 재사용 가능한 권한/효과 계약, 무설정 상태의 안전한 기본값이다. 현 시점의 종합 운영 완성도는 Newgame이 앞서며, 이 후보는 공통 코어의 재사용성과 판정 엄밀성을 높인 단계다.

Newgame 공개 대문과 역할 로그인 경계는 실제 브라우저로 확인했다. 보호된 내부 문서에 새로 로그인하거나 자격증명을 바꾸지 않았다. 내부 화면의 현재 운영 상태와 배포 성공은 로컬 소스 감사와 구분해 미확인으로 둔다. 로컬 합성 화면 관찰과 테스트는 사용자 수락을 대체하지 않는다.

현재 프로젝트 도입은 별도 Task/Execution으로, 기존 v0.4.0 원장/engine/policy와 오프라인 로그인 생략 결정을 보존한 검토된 구성 요소 도입으로 진행한다. 전체 원장 migration, 실행 권한 확대, 계정·외부 배포의 자동 활성화는 하지 않는다.
