# RFC-0017 — SFH 전체 계약 추출·일반화·V2 반영 실행 일정

2026-09-16 / TASK-20260916-SFH-EXTRACTION-001 / EXE-20260916-SFH-EXTRACTION-001

사용자 지시: **중요 공백만 보완하지 않고 SFH 기반 전체 추출을 먼저 일정화한 후 작업 시작.** 이전 RFC-0016의 범위 축소를 보완한다. V2→V3 고정 전환은 유지하되 SFH 계승을 그 아래 필수 기반으로 둔다. 이 계획은 작업 순서와 통과 조건이며 정기 예약/백그라운드 실행이나 특정 날짜의 완료 약속이 아니다.

## 1. 전체의 정의

기준 Newgame commit `be23c7cad570c47e117d7521d998f5062ee23ec0`의 **모든 Git 추적 파일**을 대상으로 한다. 초기 목록은 1,362개이며 문서/코드/테스트/데이터/설정/자산/생성물의 포함 또는 제외 근거를 남긴다. 알려진 결함에 해당하는 파일만 고르는 방식은 사용하지 않는다. 추적되지 않은 로컬 빌드/비밀 설정은 별도 수량만 확인하고 원문 수집하지 않는다. 기준 commit 변경/추적 파일 누락/대상 파일 변경은 기존 추출 근거를 stale로 만든다.

전체 범위 = 운영 지시·요구/결정·원본/데이터·모듈 경계·검사·UI/접근성·위키·역할/보안·CI/출시·복원·비용/성능·피드백/진화·배포/도입. Godot 게임 규칙과 밸런스 값을 범용 코어에 복사하는 것은 범위가 아니다. 그 파일도 검토 대상에 포함하고 일반화할 계약과 프로젝트에 남길 구현을 구분한다.

## 2. 추출 단위와 증거

각 계약은 `id, family, source commit/path/hash/section, original meaning, generic invariant, disposition, prerequisites, input/output, authority, failure/retry, tests, implementation, status`로 관리한다.

분류는 core / adapter / project_only / reference_only / generated / review_required다. 자동 경로 분류는 **검토 대기**이며 의미 추출 완료가 아니다. 프로젝트 고유 파일도 삭제/누락하지 않고 계약군과 담당 단계에 배정한다. generated 파일은 원본 생성기를 따라가고, 바이너리는 자산 라이선스/검증/배포 계약으로 연결한다.

진행률은 `inventory_covered`, `semantically_reviewed`, `contract_extracted`, `implemented`, `tested`, `accepted`를 별도로 계산한다. 100% 파일 배정이나 객체 ID 일치로 전체 기능 완료를 주장하지 않는다. 기존 v0.12 비교 89개는 참고 증거이며 신규 실행기의 동등성으로 이전하지 않는다.

## 3. 선행 순서와 완료 게이트

아래는 순차 작업 묶음이다. 예상 소요량은 각 묶음의 원본 검토 후 갱신한다. 외부 계정/배포/비용이 필요한 단계만 실제 대상과 권한을 인터뷰한다. 오프라인 명세·모의 검증은 먼저 진행한다.

## 4. SFH를 그대로 복사하지 않는 경계

- SFH의 commit/push/PR/merge 상시 허가는 해당 프로젝트 권한이다. 씨앗에는 '승인된 전달 workflow와 검사·배포 receipt' 계약만 추출한다.
- SFH의 Sheet 구조와 Godot Resource는 adapter 예시다. 공통 코어에는 후보/확정 데이터 분리·버전 pin·compile/equivalence/rollback 불변식을 둔다.
- 공개·기획자·개발자 계정 이름/초기 비밀번호/Cloudflare 자원/도메인은 배포 기본값으로 복제하지 않는다. 역할·문서 범위·효과는 오너 인터뷰로 결정한다.
- 실제 게임 값·Notion 본문·비공개 원문을 seed payload에 넣지 않는다. maintainer 측 reference fixture는 로컬 비교용이며 별도 export 권한 없이는 전송하지 않는다.
- SFH의 문서상 완료 표기와 새 코어의 실제 검사·인간 수락을 구분한다. 의미 동등성과 동일 상태 문자열은 다른 판정이다.

## 5. 이번 착수의 실행 범위와 정지점

계획 기록 후 S00/S01의 전수 배정과 S02의 **손실 없는 출처 보존 추출·검증 도구**부터 구현한다. 이후 단계는 이 추출 결과를 근거로 공통 코어·프로젝트 adapter·검증기에 연결한다. 전수 파일 배정, 구조화된 SFH 모델 추출, 전체 기능 실행 동등성을 각각 보고한다.

회귀 시 현재 2.0.0-dev.1 설치와 현 프로젝트를 보존한다. 새 모듈은 새 개발 배포 버전에 포함하며 기존 원장 pin을 다시 쓰지 않는다. 소스 원본·검증 기준을 바꿔 성공을 맞추거나 새 계획 작성만으로 SFH 기반성을 인증하지 않는다.

## 6. 2026-09-20 ATP 셋업 인계 범위

후속 요청에 따라 현재 구현을 검증하고 ATP에서 도입할 수 있는 비활성 셋업을 준비한다. 배포본은 2.0.0-dev.2이다. S00 전수 배정, S01 23개 계약군의 기준 목록, S02 원본 객체·관계의 손실 없는 구조 추출을 검증했다. 이는 모든 파일의 의미 검토나 S03~S11 기능 구현 완료를 뜻하지 않는다.

ATP에는 SFH 원본 데이터를 복제하지 않고 고정 payload, ATP 자체 원본·검사 연결 목록, 읽기 검사, 6종 객체 위키 초안을 둔다. 제품 명령 하네스·운영 배포·승인 원장을 활성화하는 작업은 포함하지 않는다. ATP의 기존 기획·배포 작업과 동시 변경은 보존한다.

인계 완료와 전체 기능 동등성을 구분한다. 남은 S01 상세 추출, S03~S11 및 독립 평가·실제 Canary·인간 수락은 미확인으로 보존한다. 이번 종료를 근거로 기능 동등성을 인증하지 않으며 자동 후속 실행이나 예약 작업은 만들지 않는다.
