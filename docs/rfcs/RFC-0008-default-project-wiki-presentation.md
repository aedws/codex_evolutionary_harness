# RFC-0008 — 새 프로젝트의 기본 위키 표현

상태: v0.7.0 구현 대상. contract-6 원장/접근 모델을 유지하는 추가 표현 구성요소.

## 문제와 목표

큰 문서/작은 문서/근거 계약과 bootstrap 검사는 있었지만, 배포 씨앗에 공통 화면과 문서 작성 틀이 없었습니다. 프로젝트마다 다시 구성하면서 큰 문서가 빈 안내에 머물고 작업 순서·완료 기준이 빠질 수 있었습니다. 사용자는 Newgame식 구성을 씨앗의 기본값으로 요청했습니다.

## 결정

wiki_template.py는 도메인 중립인 대문·9개 주제·작업 상세·역할별 탐색을 제공합니다. 빈 scaffold는 검증 실패하며 프로젝트 목적/범위/미확인, 각 주제의 현재 범위/행동/근거, 작업 DAG/종료 기준/오너 판단을 채워야 합니다. 원본 레코드나 과거 검사 수·회사/종목·계정은 복사하지 않습니다.

기본값은 표현 구조와 문서 계약입니다. 역할과 접근 모드는 기존 오너 인터뷰를 따릅니다. 사용자가 확정한 공통 UX를 배포하는 것과 금융/게임 프로젝트의 정책·운영 성공을 Core로 승격하는 것은 다릅니다. 두 도메인 fixture와 권한 반례로 구조 재사용을 검사하되 교차 프로젝트 운영 수락은 미검증으로 유지합니다.

## 명령·소유권·실패

scaffold는 새 편집 원본만 생성합니다. check는 읽기 전용이며 불완전/순환/누락/권한 모순을 거부합니다. build는 새 불변 출력 디렉터리를 생성하고 동일 결과만 no-op으로 재사용합니다. 변경/수동 편집/부분 쓰기는 덮어쓰지 않고 새 디렉터리 복구를 요구합니다. 다중 파일 원자 교체나 HTTP 제공은 이 명령의 보증 범위가 아닙니다.

HTML은 평문 escape와 허용 역할 링크로만 생성합니다. 비허용 작업의 내용/참조/제목을 역할 출력에 넣지 않습니다. 전체 입력/출력 해시 manifest는 로컬 제어 자료로 남깁니다. 실제 HTTP adapter와 bootstrap artifact gate는 프로젝트가 별도로 연결합니다.

## 호환성과 rollback

배포 버전은 0.7.0, 계약 번호는 6입니다. harness.py/bootstrap.py/wiki_core.py/wiki_access.py와 옛 태그를 바꾸지 않습니다. 신규 bootstrap은 표현 검사를 함께 등록합니다. 기존 프로젝트는 새 파일을 명시적으로 적용하거나 자신의 renderer와 동등성을 검사하며 덮어쓰기 설치를 하지 않습니다. 실패 시 이전 검증 출력과 renderer pin으로 전환하고 새 증거를 보존합니다.

## 검증과 한계

검사: 다른 도메인 이름/목적으로 재사용, 빈 scaffold 거부, owner pending 거부, DAG/완료 기준 누락, HTML 주입, 역할 간 비공개 내용/링크 유출, byte-identical no-op, 수동 drift 거부. 배포 검사와 fresh install 검사도 수행합니다. 인간 가독성, 실제 여러 프로젝트 운영, 완전한 wiki 상태 reducer/HTTP 접근/자가진화 인증은 별도입니다.
