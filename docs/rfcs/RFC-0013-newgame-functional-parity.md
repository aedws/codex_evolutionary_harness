# RFC-0013 — Newgame 기능 동등성을 목표로 한 운영 씨앗

TASK-20260915-NEWGAME-PARITY-001 / EXE-20260915-NEWGAME-PARITY-001

오너 요청: Newgame과 동일한 하네스 기능을 재사용 가능한 씨앗으로 제공하고, 최적화 후에도 기능과 엄밀성을 유지한다. View to OOP, Set up to DOP는 변경하지 않는다. Newgame 기준은 로컬 be23c7c, 씨앗 기준은 9559f03이다. 문서/테스트 개수나 부분 구현률은 동등성 점수가 아니다.

## 기능 기준과 경계

| ID | Newgame 기능 | 공통 씨앗의 수락 기준 |
|---|---|---|
| P01 | 문서·코드·자료 수집 | 승인된 경로만 읽고 stable ID·원본 hash·누락·충돌 보존; 스캔에서 의미적 사실을 만들지 않음 |
| P02 | 큰 문서→작은 문서 | 임의 깊이 collection/document/module 계층; 상위 복귀·고아·순환 검사 |
| P03 | 작업 개요·판단 대기 | 결정 필요/준비/진행/검토/차단/보류/수락을 Event에서 파생; 검사/출시와 별도 축 |
| P04 | 객체 검색·선택·계보 | 유형·업무 상태·검색; 페이지 제한; 선택 객체의 출처·선행 조건·다음 행동·판정 이유 |
| P05 | 원본 최신성 | 실제 source hash 변경·삭제 시 이전 검사·승인 효력 차단; 다시 원본 승인과 검증 |
| P06 | 역할·읽기·행동 경계 | 오너 인터뷰 기반 principal/capability, 서버 판정; 제안자 자기승인 차단, 조회·승인·실행 분리 |
| P07 | 계획·검사·불변 증거 | 기존 local core Run과 정확한 대상 파일 연계; 테스트 참조가 있다는 이유만으로 통과시키지 않음 |
| P08 | 배포와 회수 | 불변 artifact→검사→활성화→health→실패 rollback; 불명 결과의 자동 재시도 금지 |
| P09 | 보호된 검색·원본 | 허용 문서와 관계만 투영; 숨긴 ID·검색결과·건수로도 노출 금지 |
| P10 | 위키 품질 | 빈 marker/누락/중복/틀린 상태를 자동 거부; 실제 화면 관찰은 별도 |
| P11 | 원본 외부 어댑터 | Git/Markdown/JSON/CSV 로컬 수집과 Notion/Sheet/CI/배포 adapter 계약; 외부 권한은 상속하지 않음 |
| P12 | 운영 개선 | 동일 workload의 출력·실패·권한 동등성 후 시간/읽기량/규칙/개입 비교; 측정 전 optimized 금지 |

게임 계산·밸런스 편집기·Godot 실행기는 도메인 기능이다. 공통 씨앗에는 도메인 어댑터 경계를 제공하며 게임 전용 동작을 코어에 하드코딩하지 않는다. Newgame의 Markdown 완료→implemented 변환은 복제하지 않고, 해당 선언은 의도/인간 판단 이벤트로 분리한다.

## 변경 구성

기존 harness.py, bootstrap.py, wiki_core.py, wiki_access.py의 핀은 유지한다. 별도 workspace 구성 요소는 승인된 원본 인벤토리·업무 이벤트를 기록하고 기존 Core.status를 읽는다. 업무 상태를 OOP 객체 속성에 직접 저장하지 않는다. CLI와 HTTP는 같은 action/permission/revision/idempotency 검사를 사용한다. 미구성 권한·어댑터는 차단한다.

기존 정적 wiki-quality-1은 상태 노드의 실제 구성 검사를 추가한다. 운영 위키에는 별도 프로필을 사용한다. 기존 프로젝트의 핀·권한·문서는 자동 이관하지 않는다. 새 배포 버전 설치는 새 경로로 하며 이전 seed를 보존한다.

## 검증 및 최적화 판정

기능은 positive/negative/adversarial/replay/stale/permission 실패 사례를 함께 검증한다. 합성 물류·게임 도메인 fixture로 공통 동작을 비교하고 실제 프로젝트 검증과 구분한다. 단일 프로젝트 성공으로 Core 일반성을 확정하지 않는다. 기존 negative probe(9개 상태 지도 삭제에도 통과)는 필수 회귀 사례다.

Newgame의 현재 클라우드/CI 성공은 이번 로컬 감사에서 재확인하지 않았다. 실제 계정 권한·배포·오너 화면 수락·외부 어댑터 검증이 없는 항목은 pending이며, 로컬 fixture 통과로 전체 parity를 선언하지 않는다. 기능 동등성 근거가 없는 최적화는 채택하지 않는다.
