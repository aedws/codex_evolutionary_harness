# RFC-0014 — 기능 보완과 동일 결과 판정

TASK-20260915-PARITY-CHECK-001 / EXE-20260915-PARITY-CHECK-001

Newgame be23c7c와 씨앗 4b4db5d를 기준으로 한다. 동일성은 객체 수나 테스트 수가 아니라 동일 입력의 ID·목적·관계·원본·권한·실패 결과로 비교한다. Newgame의 문서상 완료를 machine verified로 옮기지 않는다. 그 차이는 의도한 DOP 신뢰 경계로 명시한다.

## 구현 계약

- 승인된 로컬 JSON 레코드/Markdown 표의 선언적 매핑에서 업무 객체를 생성한다. 매핑 원본도 해시에 포함한다. 상태·권한·Core Task 바인딩을 원문 문자열에서 자동 승인하지 않는다.
- registry 1은 유지하고 registry 2에 typed relations와 객체 계약을 추가한다. 관계의 원본·provenance를 보존한다. 생성·수집·투영은 서로 다른 단계다.
- 관계·수락 계약 변경은 이전 action snapshot을 무효화한다. 충돌은 시작/제출/수락을 막는다. supersedes는 새 결정의 인간 수락 전에는 교체 효력이 없다. 이력은 삭제하지 않는다.
- 위키는 탭 전환에서 검색·유형·상태·선택을 유지하며 양방향 관계와 원본 이동을 제공한다. 보이지 않는 관계 끝점과 원본은 공개하지 않는다.
- 기존 원장·엔진 핀은 자동 이관하지 않는다. 배포 후보는 별도 버전으로 설치하고 이전 릴리스와 감사 자료를 보존한다.

## 동일 결과 검사

1. 실제 Newgame 모듈 지도와 마일스톤 표를 읽기 전용 입력으로 삼아 기준 생성기의 ID·제목·목적과 대조한다. 원문 상태는 별도 선언으로 보존한다.
2. 독립 기대값을 가진 정상/누락/중복/충돌/대체/변경/권한 fixture를 검사한다. 자기 출력 비교만으로 동등성을 확정하지 않는다.
3. 이전 registry 1 동작과 Core Run, stale, 자기승인 금지, idempotency, rollback 검사를 유지한다.
4. 최적화 전후 동일 입력의 전체 projection 및 실패 결과를 비교한다.

외부 Notion/Sheet/Cloudflare 운영, 전체 서비스 복구, 교차 프로젝트 승격은 실제 어댑터·권한·관측이 필요하다. 로컬 snapshot 또는 fixture를 그 실운영의 성공으로 표현하지 않는다. 이번 로컬 검사 결과와 미확인 기능을 분리하여 기록한다.
