# Evolutionary Harness seed

**View to OOP, Set up to DOP.**

Humans work with Requirement, Task, Decision, Module, Test and Release views. The system reconstructs trustworthy state from Reality → Evidence/Event → versioned derivation → OOP View. Human/agent actions travel through explicit policy and execution boundaries back to reality.

Every project starts from a common core and specializes through overlays. Project improvements become Domain/Core candidates only after broader evidence. New upstream rules return through compatibility checks, canary and rollback. Less context, fewer rules and lower intervention at the same trust level count as improvements.

Read [source authority](source-authority.md), [policy](policy.md), [checkpoint](checkpoint.md), then the [minimum contract](contract.md). The empty registries contain no inherited project tasks or verification claims.

The distribution version is 0.1.0, contract version 1. V2 evidence-driven execution, V3 project self-improvement and V4 hierarchical evolution are capability targets. This seed does not implement their automatic engines, a wiki UI or the proposed `eh` CLI. Important policies still need tested tool-level enforcement.

`overlays/project.json` belongs to this project. Populate it only with observed or explicitly confirmed facts. Core contract changes should be proposed upstream rather than silently forked.
