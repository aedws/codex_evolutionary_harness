# 작업 경계 피드백

작업 종료 시 오류·수정 요청·스킬 사용/변경·불필요한 재시도를 한 번 검토합니다. 관측은 category, task, evidence_ref, summary와 함께 `observe`로 기록합니다. 스킬 관련 관측에는 실제 읽은/실행한 스킬의 소유자·버전·파일 hash·사용 이유·결과를 evidence_ref가 가리키는 로컬 근거에 남깁니다. 단순 가용성은 사용 증거가 아닙니다.

표현 선호/워크플로 마찰만 제한된 구성 후보에 연결합니다. 제품 버그·권한 위반·스킬 교체는 별도 수정 과제로 남기고 사용자 취향으로 약화하지 않습니다. 없으면 summary에 `no_candidate`와 이유를 기록합니다. 반복성이나 일반화 증거가 없는 로컬 개선을 코어로 승격하지 않습니다.

코어 결함은 HARNESS-REQ로 제안할 수 있지만 이 CLI는 upstream 전송·merge·release·adopt를 자동 수행하지 않습니다. 제출과 승격은 서로 다른 권한입니다. 원문 데이터·키·원본 프로젝트 권한을 씨앗에 포함하지 않습니다. 기존 배포본은 변경하지 않고 새 배포 버전에서 시험한 뒤 명시적으로 채택합니다.
